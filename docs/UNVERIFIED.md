# FileLens 未验证项清单（1.3.0 → 1.3.8）

> 用途：真机验收时逐条打勾。只列「写进代码、但从未在真机上验证过」的用户可见行为。
> 口径：`git log v1.2.3..HEAD` 逐个提交核对；纯文档、重构、删功能（大文件排行）不计。
> 排序：按风险从高到低，不按版本。R = 可能丢数据，M = 可能让操作失效，L = 观感。
> 基线：1.3.8 / versionCode 20（0dae9bd 之后已提交 9805e29、10cd756、f5f6e3f、1bd59aa、52e3cbb）。

## 二、高风险：可能永久丢数据

| 项 | 版本 | 代码位置（文件:行号） | 怎么验（操作 + 预期） |
| --- | --- | --- | --- |
| R1 删除→回收站→撤销/恢复/清空 | 1.3.0 | `MainActivity.kt:1106-1177`、`core/Trash.kt:80-123`、`ui/TrashPage.kt:102-150` | 1. 空间页长按选 1 个小文件 → 删除 → 确认「移入回收站」；2. 5 秒内点「已移入回收站 · 撤销」→ 回原目录，预期同名文件回来、大小一致；3. 再删一次等撤销条消失 → 设置 → 回收站 → 「恢复」→ 回原目录核对；4. 在回收站「彻底删除」→ 预期文件消失且原路径没有；5. 造一次原路径不可写（如原目录已删）再恢复 → 预期弹「另存到 Download」并能落盘 |
| R2 回收站 30 天过期自动清理 | 1.3.0 | `core/Trash.kt:23,76-77,230-239`、`MainActivity.kt:143,499-508` | 把手机时间调到 31 天后冷启动 App → 预期 toast「已自动清理 N 项过期文件」，回收站内该项消失、其它项不动；反向调到 29 天 → 文件仍在 |
| R3 系统回收站分支（相册文件） | 1.3.0 | `MainActivity.kt:1112-1115`、`core/SystemTrash.kt:25-50` | 选一张相册图片删除 → 预期先弹系统「移入回收站」确认框，App 提示「请在系统弹窗确认」；确认后系统相册回收站能看到它，App 回收站页也列出这条系统条目并能恢复 |
| R4 预览页删除 | 1.3.2 | `ui/PreviewPage.kt:247-260` | 浏览 → 打开一张图 → 「删除」→ 确认 → 预期进 App 回收站；回回收站能找到并成功恢复 |
| R5 清理页批量删除 | 1.3.0 | `ui/CleanPage.kt:643`、`ui/CleanPage.kt:1119` | 清理 → 应用/垃圾段多选若干 → 删除 → 确认 → 预期进回收站且「撤销」可用；撤销后文件回到原处 |

**如果这些不通过，后果是什么：**

- R1：文件移进回收站后既回不到原路径、也可能从回收站消失，等于不可逆删除。
- R2：清理逻辑可能把还没到期的文件提前真删，或过期文件永远不清理一直占空间。
- R3：图片可能被系统直接删除而不是进回收站；或 App 显示已删、实际仍在。
- R4：在预览里删掉的图无法从回收站找回。
- R5：清理页批量误删后「撤销」无效，整批文件丢失。

## 五、说明

- 1.3.8 三项在模拟器上做过程序化自测（面包屑文本、遮罩亮度差 35%、按钮同款 `rounded()`），但没有真机验收，仍列在 L5-L7。
- 本清单不含「大文件排行」（1.3.2 加、1.3.3 删）和纯删除类改动（清理页回收站入口）。
- 每验完一条，在项号后写「通过 / 不通过 + 日期」；不通过的另开任务书，不在本文件里改代码。
