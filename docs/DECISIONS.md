## D-01　传输走个人版，但保留配对码握手

**日期**：2026-11-07　**状态**：已定

**决定**
- 不做安全版（无登录墙、无会话令牌轮换）
- **保留**配对码输入框，但配对码**不上传**：走挑战-应答
  ```
  GET /api/challenge  → { nonce }
  proof = SHA256(pin + ":" + nonce)
  POST /api/login     → { proof, nonce }
  ```
- 握手成功后转明文

**为什么**
- 个人版的核心诉求是「局域网内免登录」，不是「不设防」
- 配对码明文过 HTTP 等于裸奔，改挑战-应答几乎零成本

**否决了什么**
- ❌ 完全开放（无配对码）：任何人连上同一 Wi-Fi 就能拷文件
- ❌ HTTPS + 自签证书：浏览器警告 + WebView 要额外放行，成本大于收益
- ❌ 全链路加密：用户明确接受握手后明文

**代价 / 限制**
- 只防「偷看配对码」，不防「嗅探文件内容」
- 前端要自带纯 JS SHA-256（**`crypto.subtle` 在 `http://` 下是 undefined**）

## D-02　玻璃质感：主线用伪玻璃，不做真模糊

**日期**：2026-11-07　**状态**：已定

**决定**
- 主线（所有正式版本）用**伪玻璃**：半透明 + 顶部高光渐变 + 底部内阴影 + 0.5dp 亮边 + 3% 噪点
- 真模糊只在独立分支 `demo/blur` 做过演示版，**不合并**

**为什么**
- Android 的 View 体系**没有** iOS `UIVisualEffectView` 的等价能力
- `RenderEffect` 模糊的是**控件自己**，不是背后的内容 —— 对一块半透明纯色做模糊等于没做
- 真模糊只能「截背景 → 模糊 → 当底图」，每次打开 +100~200ms、内存 +8MB、滚动中无法实时

**否决了什么**
- ❌ 声称"API 31+ 支持真模糊"（这是错的，别再提）
- ❌ 用第三方 Haze 之类库：主要面向 Compose，View 体系适配成本高

**代价**
- 半透明面板在有高对比内容（彩色缩略图）背后会"透字"，必须靠提高不透明度（`.10 → .26`）制造隔层感
- 用户已接受此限制

## D-03　照片清理：不做训练模型，做「打分 + 原型检索」

**日期**：2026-11-07　**状态**：方案稿，未排期

**决定**
- 规则打分（截图/长期未动/重复/模糊）→ 可解释排序
- 用户删过的图存为**负样本原型簇**，新图算余弦相似度命中
- 类别权重随接受率自适应
- **不训练任何神经网络**

**为什么**
- 单用户一年删几百张，样本量 < 特征维度，**无法训练**
- 只有负样本（删了）没有正样本（明确保留），标签是偏的
- 反馈环会让模型越用越偏（推荐→用户照删→强化该偏向）

**否决了什么**
- ❌ 用删除日志训练分类器
- ❌ 手工特征词典 + LLM 打标（每张图都要过模型，成本不成立）
- ❌ 云端多模态判断（相册上传第三方，隐私不成立）

**代价**
- 效果上限低于"理想中的 AI"：它只能说"像你删过的"，不能说"这张没用"
- 详细方案见 `PHOTO-CLEAN-PLAN.md`

## D-04　不删除、不替换原有组件

**日期**：2026-11-07　**状态**：已定，写入 `AGENTS.md`

**决定**
- 不要新增 UI 组件，除非任务书明确要求
- 不要删除/隐藏/替换原有组件，除非它功能完全不可用
- 要调整就改参数（颜色/尺寸/文字），不改结构

**为什么**
- 原有组件是别人按真实需求造的，删掉往往连带丢掉没注意到的功能
- 两次实锤：
  1. 把网页底部导航整条隐藏 → 连带丢了面包屑和入口
  2. 在「我的」页注入「本机连接信息」卡片 → 用 `location.host` 拼出 `127.0.0.1`（回环地址，别的设备连不上），还和原有区块重复出两个二维码

**教训一句话**
> 从现成的东西上做加法，比推倒重来安全。

## D-05　签名固定，不再更换

**日期**：2026-11-07　**状态**：已定

**决定**
- 一律用 `ANDROID_USER_HOME=.android-home`（证书指纹 `FA1B29…`）签名
- 换环境（worktree / 分支）时**必须显式指定**，否则 Gradle 会生成新 key

**为什么**
- 签名一变，覆盖安装被系统拒绝（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）
- 已经因此让用户卸载重装两次，第二次还丢了权限授权

**代价**
- 备案（App 备案要填公钥+MD5）前必须先定死正式签名

## D-06　一次只交付一个可验收的版本

**日期**：2026-11-07　**状态**：已定

**决定**
- 一个版本只做一组相关改动
- 补全任务必须先做完再往下，不许"先发个缺功能的包"

**为什么**
- 1.3.0 定了四块（回收站/树图下钻/排行/预览），实际只做完两块就跳去做传输改造，
  最后发出去的包"看起来是 1.3.0、实际缺两块"
- 这条后来是开发自己提出来的，我接受了 —— **它比我更早发现这个问题的严重性**

## D-07　树图渲染：视觉面积与真实字节解耦

**日期**：2026-11-07　**状态**：已定

**决定**
```
p'_i = max(p_i, 0.8%)      // 地板
归一化后用 p''_i 布局
```
- 小于 0.1% 且超过 30 个的项合并为「其他 N 项」
- 任何块不小于 44×44dp（低于此改列表呈现）

**为什么**
- 真实面积下，1MB 的文件在 100GB 盘上就是一条线，看不见也点不中
- 用户原话：「把细小文件做大，忽略一点实际，让视觉符合逻辑」

**代价**
- 面积不再是精确比例 —— 这是**有意的失真**，换取可读与可点

## D-08　网页资源零改动，行为改动走运行时注入

**日期**：2026-11-07　**状态**：已定

**决定**
- `app/src/main/assets/www/` 下一个字节都不改
- 需要改行为（隐藏元素、接管点击、加样式）一律 `evaluateJavascript` 注入

**为什么**
- 那套资源是从 DropLink 搬来的，改了就和电脑端不一致
- 注入可以随版本调整，不用重打包网页

**约定**
- 注入用 `id` 防重复（如 `dl-embed-style`）
- 注入失败要能降级，不能白屏
